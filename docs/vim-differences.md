# Vim との違い

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-11-16 |
| 位置づけ | Vim 9.1 との食い違いのうち、見つけたが直さないと決めたものの一覧 |
| 比べた Vim | Vim 9.1 を Ex モードでない起動（`vim -Nu NONE -i NONE -n --not-a-term`）で動かし、`feedkeys(keys, "xt")` で入力した結果 |

要件定義 1 章は、Vim との 100% の互換を目指さないとしている。
このため、Vim との細かい食い違いは、日常の編集で困るもの（バッファの内容が変わるもの、よく打つ操作で起きるもの）だけを直し、残りをここに書く（#89）。

個々の関数の振る舞いの違い（要件が Vim と違う挙動を定めているもの。FR-09 の正規表現の文法など）は、その関数の doc コメントに書く（`internal/command` のパッケージの doc コメント）。
この一覧には、doc コメントの 1 か所に収まらない違いと、#89 とそのレビュー（PR #100）で見つけた未実装の機能を書く。
未実装の機能を全て並べたものではない（実装する操作の一覧は #9 の案にある）。

## 直したもの

#89 で直したものを、比べるときのために残す。

- ビジュアルモードのカーソルは、j、k、`$` で移った短い行や、`l` で最後の文字から進んだ行では、Vim と同じく行末の後（NUL の位置）に置く。文字単位の選択の始まりがここにあれば、その行の改行から選び（`a` と `bcd|e` の `vkd` は `a` を残す）、終わりがここにあれば、その行の改行まで選ぶ（`ab|c` と `d` と `e` の `vjd` は `abe` になる）。ここから `h` で戻る列も Vim と同じになる（`ab` と `cdef|g` の `vkhCX<Esc>u` のカーソルは 1:1）。表は `internal/command/visual_eol_test.go` にある
- 選択の終わりが行末の後のとき、`>` と `<` は終わりの行まで字下げし、次の行は字下げしない（`ab|c`、`d`、`e` の `vj>` は `e` を残す）
- 複数の行の選択のドットリピートは、終わりの列が繰り返す先の行の長さ以上のときだけ、その行の改行まで消す（Vim の `resel_VIsual_vcol`。`$` の後だけは常に改行まで消す）
- ビジュアルモードの間に拡張機能の編集が届いても、行末の後のカーソルを最後の文字へ丸めない（`State.SetCursor`）。拡張機能へ返す `editor/state` の選択は、終わりが行末の後ならその行の改行まで含め、`d` が消す範囲と揃える
